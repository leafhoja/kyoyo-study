# 国家総合職〈教養区分〉学習サイト 設計書

## このフォルダの目的

国家公務員採用総合職試験〈教養区分〉の合格を目的とする、個人学習用の静的Webサイトを**将来制作するための設計書一式**を格納する。

**現状：本フォルダにはWebサイト本体（HTML/CSS/JS・実データ）が実装済みであり、現在は統合・改善を進めている。** `docs/`配下の設計書と`references/`配下の参考資料に加え、`第0部`〜`第7部`の学習ページ、`過去問/`の原本・解説・Web版、`data/`の問題データを含む。

本プロジェクトは独立したGitリポジトリで管理し、GitHub Pagesで公開する。親リポジトリ`leafhoja/study`の除外設定は維持し、このフォルダ自身のGitリポジトリから公開する。原本PDF・一時ファイルはGit管理から除外し、Webサイトには学習用HTML/CSS/JS・問題データ・検索索引・過去問Web版の画像だけを出力する。設定と更新手順は[公開手順.md](公開手順.md)を参照。

## フォルダ構成

```
docs/
├── 内容設計/            ← 何を・どういう順で教えるか（コンテンツ面）
│   ├── 00〜10番          ← サイト全体の内容方針（調査結果〜学習履歴の内容設計）
│   └── chapters/         ← 全17章（ch00〜ch16）の章別詳細設計。1章1ファイル
├── 技術設計/            ← どう実現するか（技術面）
│   └── 11〜15番          ← UI/UX・技術基本・データ・アクセシビリティ・品質保証
├── 16_運用更新設計.md    ← 内容面・技術面の両方にまたがる横断文書のため docs/ 直下に維持
├── 17_制作ロードマップ.md
└── 18_未決事項と意思決定記録.md
references/               ← 公式資料一覧・用語定義・出典管理方針
```

内容設計と技術設計を分けたのは、章の内容（何をどの順で教えるか）と実装方式（localStorage・アコーディオン実装等）を独立して検討・更新できるようにするため。両者の対応関係は`内容設計/02_情報アーキテクチャ設計.md`§6、`技術設計/12_技術基本設計.md`§6等、各文書の「他の設計書との関係」節で明示している。

## 設計書の読み順

1. `docs/内容設計/00_調査結果.md` — 既存プロジェクト調査・教養区分の公式試験情報（すべての前提）
2. `docs/内容設計/01_全体基本設計.md` — サイト全体の目的・方針（最上位文書）
3. `docs/内容設計/02_情報アーキテクチャ設計.md` 〜 `05_章構成一覧.md` — 情報構造・学習体験・コンテンツ方針・章構成（確定）
4. `docs/内容設計/06_過去問設計.md` 〜 `10_学習履歴進捗設計.md` — コンテンツ種別ごとの詳細設計
5. `docs/内容設計/chapters/ch00_試験概要.md` 〜 `ch16_直前期本番心構え.md` — 全17章の章別詳細設計（1章1ファイル、実装レベルまで詳細化）
6. `docs/技術設計/11_UI_UX設計.md` 〜 `15_テスト品質保証設計.md` — 技術設計（UI・技術構成・データ・アクセシビリティ・品質保証）
7. `docs/16_運用更新設計.md` 〜 `18_未決事項と意思決定記録.md` — 運用・制作ロードマップ・未決事項
8. `references/` — 公式資料一覧・用語定義・出典管理方針

## 上位設計と下位設計の関係

`内容設計/01_全体基本設計.md`が最上位文書であり、`内容設計/02`〜`18`番の各設計書・`技術設計/`配下・`内容設計/chapters/`配下の章別詳細設計は、いずれもこの文書の方針を具体化したものである。矛盾が生じた場合は`01_全体基本設計.md`を優先するか、`18_未決事項と意思決定記録.md`に記録した上で改訂する。`00_調査結果.md`はすべての設計判断の前提となる調査結果であり、事実上`01`番よりさらに手前の起点に位置する。

## 現時点の決定事項

- 独立リポジトリ＋GitHub Pagesによる公開（2026-10-03、利用者の指示で変更）
- 過去問・過去問解説は既存の内容とパスを正本として保全し、サイト統合時も移動・削除・上書きしない
- 通常の学習ページと過去問Web版は、共有デザイントークン（`site-theme.css`）を使って配色・文字・境界線・影を統一する
- 全17章（ch0〜ch16）・8部という章構成（確定版）
- 難易度Level 0〜5の6段階体系
- 過去問・練習問題・予想問題の3種の使い分けと、それぞれの断定表現ルール
- 記述式・面接系科目（総合論文・企画提案・討議・面接）は「模範解答」ではなく「思考の型＋評価観点チェックリスト」で代替する方針
- 技術構成：素のHTML/CSS/JS（ビルドステップなし）、問題データはJSON、ブラウザ内保存は当初localStorage
- 既存3サイト（金融・人工知能・株式）からの3分類（そのまま踏襲／修正して踏襲／今回は採用しない）

## 未決事項

詳細は`docs/18_未決事項と意思決定記録.md`を参照。特に優先度「高」として次が残っている：

- 記述式試験対策の評価観点チェックリストの具体的な項目の最終確定
- 学習履歴のLevel到達閾値（自力正解率の基準値等）
- Phase 1（最小実用版）で最初に着手する章の最終選定

## 次に行うべき作業

1. `18_未決事項と意思決定記録.md`の優先度「高」の項目を、実装着手前に解消する
2. `00_調査結果.md`§4.3の教養区分公式情報の再確認事項（特にU-01・U-02）を人事院一次資料で解消する
3. 利用者（本人）に、Phase 1で最初に着手したい章・分野を確認する
4. 上記が整理でき次第、実装開始の指示を待って`17_制作ロードマップ.md`のPhase 1に着手する

## 本体実装を開始するための条件

- 本設計書一式が「最終確認」（各設計書の完成条件、`18_未決事項と意思決定記録.md`の優先度「高」項目の解消）を満たしていること
- 利用者から実装開始の明示的な指示があること（既存3サイトと同じ二段階運用：設計→実装）

## 参照した既存プロジェクト

- `金融/` — マスター＋部別設計図の分割方式、3層構造、box系コンポーネント、モデル使い分けの参考元
- `人工知能/` — 同上（`設計図.md`の全体構想パターンの参考元）
- `株式/` — 同上（設計フェーズのみで実装未着手というプロジェクト状態の参考元）

いずれも読むだけのコンテンツサイト（FXアプリのみFlask+SQLiteアプリ）であり、問題演習・学習履歴・正誤記録の仕組みは本プロジェクトが初めて新規設計するものである（詳細は`00_調査結果.md`§3参照）。

## 公式情報の調査時点

教養区分の試験制度に関する公式情報は2026-07-30時点で人事院公式サイト等を調査したものである。試験制度は変更されうるため、実装前・年度更新時に`docs/16_運用更新設計.md`の手順で再確認すること。
