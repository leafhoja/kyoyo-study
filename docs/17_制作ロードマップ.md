# 17_制作ロードマップ

## 1. この文書の目的

実装（HTML化）を開始する際の段階的な制作順序を定める。今回は設計書のみを作成し、本文書に基づく実装は行わない（プロジェクト目的§0）。

## 2. 対象範囲

Phase 0〜4の開始条件・完了条件・依存関係・後回しにする機能、実装フェーズでのエージェント運用ルール。

## 3. 前提

`01_全体基本設計.md` §5.16（優先順位）・§5.17（段階的な制作計画）、追加事項A（エージェント運用制限・逐次出力）、既存3サイトの「1エージェント=1ファイル」実行単位（00_調査結果.md §3.2⑤）を前提とする。

## 4. 設計方針

- Phaseごとに開始条件・完了条件を明示し、前のPhaseが完了しないまま次に進まない。
- 実装フェーズでもエージェント同時稼働数の上限は2とし、逐次出力の原則を適用する（追加事項A・E）。

## 5. 詳細仕様

### 5.1 Phase 0：調査・設計（本設計書一式）

- **内容**：公式試験情報の確認、既存設計書の調査、全体基本設計、章構成、技術選定、データ設計
- **開始条件**：プロジェクト開始の指示
- **完了条件**：本設計書一式（00〜18番＋chapters＋references＋README）が揃い、最終確認（プロジェクト仕様書25節・追加事項F）を満たすこと
- **依存関係**：なし（起点）
- **後回しにする機能**：実装（HTML化）そのもの

### 5.2 Phase 1：最小実用版（MVP）

- **内容**：第0章（ch0）＋ch1（文章理解）の骨格、少数の問題（Level0〜2程度）、解答の開閉、正解・不正解記録、同一ブラウザ内保存、スマートフォン対応、基本ナビゲーション（`18_未決事項と意思決定記録.md`U-23で確定：最初の2章はch0・ch1）
- **開始条件**：Phase 0完了。ユーザーから「詳細を詰め、準備ができ次第実装を開始してよい」との指示を受領済み（2026-07-31）
- **完了条件**：第0章が閲覧でき、少なくとも1つの分野でLevel0〜2の問題演習と正誤記録・ブラウザ内保存が動作し、スマートフォンで表示・操作できること
- **依存関係**：Phase 0の全設計書、特に12番（技術基本設計）・13番（データ設計）
- **後回しにする機能**：全章の本文、Level3以降の問題、過去問・予想問題、検索・絞り込み、学習履歴ダッシュボードの詳細分析

### 5.3 Phase 2：教材拡充

- **内容**：各章の本文（全17章）、練習問題（Level0〜5）、過去問の整理、詳細解説、タグ、検索、絞り込み
- **開始条件**：Phase 1の完了条件を満たすこと
- **完了条件**：全17章の本文とLevel0〜5の練習問題が揃い、過去問ライブラリが分野・年度等で検索・絞り込みできること
- **依存関係**：Phase 1のUI・データ基盤
- **後回しにする機能**：予想問題、復習機能の高度化、時間制限付き演習

### 5.4 Phase 3：復習機能強化

- **内容**：誤答一覧、復習対象一覧、分野別進捗、再挑戦、学習履歴の分析、エクスポート・インポート
- **開始条件**：Phase 2の完了条件を満たすこと
- **完了条件**：学習履歴ダッシュボードが章別・分野別・Level別の集計を表示し、復習対象の管理・エクスポート・インポートが機能すること
- **依存関係**：Phase 2で蓄積される問題データ・学習履歴
- **後回しにする機能**：忘却曲線的な自動復習スケジューリング（10番§9未決事項、採用するとしてもこのPhase以降で検討）

### 5.5 Phase 4：実戦対応

- **内容**：時間制限付き演習、セット問題（本番形式）、予想問題、本番形式の演習、総合的な弱点分析
- **開始条件**：Phase 3の完了条件を満たすこと
- **完了条件**：本番形式のセット演習（基礎能力試験Ⅰ部30題・Ⅱ部20題を模したセット等）が実施でき、予想問題バンクが根拠付きで整備されていること
- **依存関係**：Phase 2・3で整備された過去問・練習問題・学習履歴基盤（予想問題は過去問・練習問題の整備が前提、01番§5.16の優先順位5番目）
- **後回しにする機能**：任意の試験日設定に基づく学習計画の自動調整（18番未決事項、必要性が確認された場合に別途検討）

### 5.6 実装フェーズにおけるエージェント運用ルール（追加事項A・Eの適用）

- 同時稼働エージェントは最大2つ（親エージェント自身を含めて数える）。
- 実行単位は「1エージェント=1ファイル以下」を基本とし、章単位より細かく分割してもよい（既存3サイトの運用、00_調査結果.md §3.2⑤を踏襲）。
- 複数ファイルをまとめて一括生成せず、完成したファイルから順次保存・報告する。
- 相互依存が弱い作業（例：ある章の本文執筆と、別の章の問題データ作成）は2エージェントまでの並列を許容するが、上位設計（章構成・データスキーマ）が未確定な段階では並列化しない（追加事項Aの趣旨）。

## 6. 他の設計書との関係

`01_全体基本設計.md` §5.16〜5.17の具体化である。`15_テスト品質保証設計.md`の運用面チェックはPhaseの完了条件判定に使用する。

## 7. 採用しなかった案

- 全章・全問題データを一度に作り切ってから初めてサイトを公開する（実装する）案：追加事項Eの逐次出力原則、および既存3サイトの段階的実装の実績（00_調査結果.md §3.2⑤）に反するため、Phase 1で小さく動くものを先に作る方式を採用した。

## 8. リスクと注意点

- Phase 1の範囲を欲張りすぎると「最小」実用版にならず、着手が遅れるリスクがある。優先順位（01番§5.16）に従い、範囲を絞ることを実装フェーズで再確認する。
