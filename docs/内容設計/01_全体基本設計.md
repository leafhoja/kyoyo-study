# 01_全体基本設計

## 1. この文書の目的

国家総合職〈教養区分〉学習サイトの全体構想を定める最上位の設計書である。以後のすべての詳細設計書・技術設計書は本文書と矛盾してはならず、矛盾が生じた場合は本文書を優先するか、本文書自体を改訂する。

## 2. 対象範囲

サイト全体の目的、想定利用者、担う役割／担わない役割、情報アーキテクチャの大枠、章構成の大枠、学習の進め方、問題演習・学習履歴の位置付け、運用方針、品質基準、完成条件、優先順位、段階的制作計画。個々の章の内容・データの詳細仕様・技術実装の詳細は、第2層（個別詳細設計書）・第3層（技術設計書）に委ねる。

## 3. 前提

- `00_調査結果.md` の内容（既存プロジェクトからの3分類、教養区分の公式試験情報）を前提とする。
- 追加事項A〜F（エージェント運用制限・逐次出力、完全な初学者前提、問題難易度の段階的上昇、練習問題設計の差し替え、作業手順・最終確認への追記）をすべての設計判断に適用する。
- 今回作成するのは設計書のみであり、Webサイト本体・実データは作成しない（プロジェクト目的§0）。

## 4. 設計方針（全体基本設計書で決めるべき13の問いへの回答）

### 4.1 このサイトは、合格のためにどのような問題を解決するのか

一般的な公務員試験対策本・過去問集・予備校教材は、①読者が既に「教養区分とは何か」を知っていることを前提にしている、②知識の伝達と問題演習が別々の教材に分かれていて往復コストが高い、③自分がどのLevel相当の問題を解けていて次に何をすべきかが可視化されない、という3つの課題を抱えやすい。本サイトは、**完全な初学者が制度理解→基礎知識→段階的な問題演習→復習という一本の道を、迷わず・後戻りせずに進めること**を最大の解決対象とする。

### 4.2 一般的な参考書・過去問集・予備校教材と何が異なるのか

- 制度説明と対策を明確に分離し（第0章）、対策パートでは説明→例題→難易度昇順の演習という一貫した型を全分野で強制する（追加事項B・C）。
- 過去問（事実）・練習問題（知識確認）・予想問題（推測、根拠明示）を出自ごとに分離し、利用者が「これは過去に出た事実」なのか「制作者の予想」なのかを常に区別できるようにする（§6過去問設計・§8予想問題設計、断定表現の禁止）。
- 正誤記録・難易度別の学習履歴をブラウザ内に保存し、「読んだ」と「解けるようになった」を区別する（§10）。
- スマートフォンでの演習を前提にしたUI（アコーディオン式解答開閉、タップ操作）を最初から設計する。

### 4.3 サイト内で完結させる範囲はどこまでか

- 制度の説明（第0章）、各分野の知識解説とLevel 0〜5の段階的問題演習、過去問の整理・解説、学習履歴・復習管理は、サイト内で完結させる。
- 総合論文・企画提案・政策課題討議・人物試験など記述式・面接系の試験は「模範解答」が公式には存在しないため、サイト内では「思考手順・構成の型・自己採点の観点」を提供するにとどめ、絶対的な正解の提示は行わない（§6.2参照）。

### 4.4 外部教材や公式資料に委ねる範囲はどこか

- 人事院公式サイトで公開されている試験問題例PDF・正答番号の一次情報は、著作権・正確性の観点からサイト内での全文転載を避け、原則として**出典明記の上での要約・自作解説＋公式PDFへのリンク**とする（§6.3）。
- 官庁訪問・キャリアパス等、年度・府省庁により大きく変動する実務情報は、公式情報への導線提供にとどめ、断定的な解説は行わない。

### 4.5 インプット・演習・復習をどのように循環させるか

追加事項D・E「作業手順への追記」に基づき、各章は次の循環を基本とする：

```
説明 → 確認問題(Level0-1) → 解法確認 → 基礎〜標準問題(Level2-3) → 正誤記録
  → 誤答原因の確認 → 復習対象への登録 → 実戦問題(Level4-5)・過去問 → 再挑戦
```

この循環は章ごとに閉じるのではなく、学習履歴（§10）を介して分野横断・時間差での再挑戦を可能にする。

### 4.6 どの単位で学習進捗を測るか

- 大分類：章（例：判断推理）
- 中分類：Level（0〜5）別の着手・正解状況
- 小分類：個々の問題（過去問／練習問題／予想問題）の正誤履歴

進捗は「章を読了したか」「Level別に何問中何問正解したか」「自力正解率」の3層で管理する（詳細は10_学習履歴進捗設計.md）。

### 4.7 「章を読んだ」と「能力を習得した」をどう区別するか

「閲覧完了」（章末まで到達した）と「Level到達」（そのLevelの問題群で一定の自力正解率を満たした）を別のフラグとして管理する。閲覧完了は最低条件であり、能力習得の証明にはしない。到達目標の達成判定は正答率だけでなく、後述の「偶然正解ではないか」等の質的シグナル（自己評価）も加味できる設計にする（§10.3）。

### 4.8 正解率だけでは測れない能力をどう扱うか

正誤の2値だけでなく、任意入力の自己評価（理解して正解／迷って正解／偶然正解／理解不足で不正解／ケアレスミス／時間不足／未回答／解答閲覧のみ）を記録候補とする（10_学習履歴進捗設計.md）。総合論文・企画提案・政策課題討議・人物試験のような記述式・面接系能力は、正誤で測れないため、「自己採点の観点チェックリスト」「振り返りメモ」という形で記録する（09_解答解説設計.md）。

### 4.9 過去問・練習問題・予想問題をどう使い分けるか

| 種別 | 性質 | 主目的 | 断定表現 |
|---|---|---|---|
| 過去問 | 公式に出題された事実 | 出題傾向の把握・本番形式演習 | 出題実績は断定可（出典明記） |
| 練習問題 | 制作者が知識確認・能力形成のために作成 | 段階的な基礎力形成 | 「本番形式ではない」旨を明記 |
| 予想問題 | 制作者の推測（根拠を伴う） | 出題可能性のある論点への備え | 「予想」であり断定しないことを常に明示 |

学習の主軸は練習問題（Level 0〜5の段階的形成）、仕上げは過去問（Level 5相当・本番形式）、応用的な備えとして予想問題を位置付ける（詳細は06〜08番設計書）。

### 4.10 情報の正確性をどのように維持するか

- 試験制度に関する情報は、`00_調査結果.md` で区分した「現在確認できる公式の事実」「年度によって変わりうる事項」「設計上の仮定」「今後追加確認が必要な事項」の4区分をサイト本文でも維持する（16_運用更新設計.mdで具体的な表示ルールを定める）。
- 断定表現の使用ルール：一次資料で確認できた事実のみ断定形を用い、それ以外は「〜とされる」「〜と見られる」「未確認」等を用いる（追加事項の趣旨、18.3節参照）。

### 4.11 年度変更にどう対応するか

- 年度依存の数値・日程・倍率は本文から分離した「制度情報ボックス」に隔離し（既存3サイトの`box-now`思想を踏襲、§3.2⑧参照）、更新時にそのボックスのみ差し替えられるようにする。
- 2026年度からの教養区分「年2回実施」化のような**制度自体の変更**は、章本文で「いつからどう変わったか」を明記し、旧制度の情報を単純に削除せず「変更履歴」として残す（過去問の年度整理とも整合させる）。

### 4.12 最小実用版では何を作り、何を後回しにするか

19節「制作ロードマップ」のPhase 0〜4に従う。最小実用版（Phase 1）は、第0章＋主要対策章の骨格＋少数の問題＋解答開閉＋正誤記録＋ブラウザ内保存＋スマートフォン対応＋基本ナビゲーションとする（詳細は17_制作ロードマップ.md）。

### 4.13 サイトの完成をどのように判定するか

「完成」を単一の状態と捉えず、Phaseごとの完了条件（17_制作ロードマップ.md）＋分野ごとの完了条件（各章詳細設計書の「完了条件」欄）の集合で判定する。全分野が本番形式の演習まで到達し、学習履歴・復習システムが安定稼働し、アクセシビリティ・スマートフォン対応・品質保証の各チェック項目（15_テスト品質保証設計.md）を満たした状態を「一区切りの完成」とする。

## 5. 詳細仕様

### 5.1 制作目的

完全な初学者が、国家総合職〈教養区分〉に必要な知識・能力を、体系立った説明と段階的な問題演習を通じて自力で身につけ、過去問レベルの問題に対応できる状態に到達することを支援する、個人学習用の静的Webサイトを設計する。

### 5.2 想定利用者

国家総合職〈教養区分〉の合格を目指す受験者1名（利用者本人）。試験対策・出題形式・解法・学習計画について予備知識を持たない状態を初期状態と仮定する（追加事項B）。想定学習期間はおおむね数か月だが、サイト内には固定的な残り日数を記載しない（00_調査結果.md §5）。

### 5.3 合格に必要な能力の整理

`00_調査結果.md` §4.1の試験構成に基づき、次の能力群に整理する。

| 試験段階 | 試験科目 | 測られる能力 |
|---|---|---|
| 第1次 | 基礎能力試験Ⅰ部（知能） | 文章理解・判断推理・数的推理・資料解釈という「思考の道具」の運用力 |
| 第1次 | 基礎能力試験Ⅱ部（知識） | 自然科学・人文科学・社会科学の知識（時事・情報6題は2026年度Ⅰ部） |
| 第1次 | 総合論文試験 | 教養・哲学的な考え方に基づく総合的判断力・論述力 |
| 第2次 | 企画提案試験 | 資料を読み解き政策を立案する企画力・プレゼン力 |
| 第2次 | 政策課題討議試験 | グループ討議での対人能力・論理的説得力 |
| 第2次 | 人物試験 | 人柄・対人的能力 |

### 5.4 サイトが担う役割

- 制度理解の入口（第0章）
- 各科目・各能力の知識解説とLevel別段階的問題演習
- 過去問の整理・独自解説・出題傾向分析
- 予想問題の根拠つき提示
- 学習履歴・復習管理（ブラウザ内保存）
- 学習計画・過去問活用法の指針

### 5.5 サイトが担わない役割

- 総合論文・企画提案・政策課題討議・人物試験の「絶対的な模範解答・採点」の提供（公式に存在しないため。§4.3）
- 官庁訪問・府省庁選択・キャリア形成に関する助言（試験対策の範囲外）
- 最新の統計・倍率・日程等、頻繁に更新される一次情報の「唯一の情報源」としての機能（人事院公式情報への導線を主とする）

### 5.6 学習体験の基本方針

- 追加事項Bの段階構造（何をするか→用語→具体例→考え方→例題→基礎→条件変化→複合→本番近似→過去問）をすべての分野で徹底する。
- 追加事項Cの難易度体系（Level 0〜5）を問題演習全体で統一的に使用する。
- 既存3サイトの「定義から入らず具体例・逸話から入る」語り口を継承しつつ、専門用語は初出時に必ず定義する（追加事項B）。

### 5.7 情報アーキテクチャ（大枠。詳細は02_情報アーキテクチャ設計.md）

- 第0部：教養区分とは何か（制度理解・学習の始め方）
- 第1部：基礎能力試験対策・知能分野（文章理解／判断推理／数的推理／資料解釈）
- 第2部：基礎能力試験対策・知識分野（自然科学／人文科学／社会科学／時事）
- 第3部：総合論文試験対策
- 第4部：企画提案試験対策
- 第5部：政策課題討議試験対策
- 第6部：人物試験（面接）対策
- 第7部：学習計画・過去問活用・総仕上げ（横断編）
- 独立領域：過去問ライブラリ／練習問題バンク／予想問題バンク／学習履歴・復習ダッシュボード／用語集／検索

この大枠は暫定版であり、05_章構成一覧.mdで確定させる。

### 5.8 全体の章構成

暫定の章数は第0部1章＋第1部4章＋第2部4章＋第3部1〜2章＋第4部1〜2章＋第5部1章＋第6部1章＋第7部1〜2章の、計14〜16章程度を想定する（確定は05番）。既存3サイトの「全N部M章」のような固定的な大構想の確定を急がず、公式試験情報（特に2026年度制度変更）の追加確認結果によって章割りを調整できる余地を残す。

### 5.9 コンテンツの種類

1. 章本文（知識解説、追加事項Bの段階構造に従う）
2. 例題（解説付き、Level 0〜1相当）
3. 練習問題（Level 0〜5、07番設計書）
4. 過去問（年度・試験段階別、06番設計書）
5. 予想問題（根拠明示、08番設計書）
6. 解答・解説（09番設計書）
7. 学習計画・過去問活用ガイド（第7部）
8. 用語集
9. 学習履歴・復習ダッシュボード（10番設計書）

### 5.10 学習の進め方

第0章で試験制度と学習の始め方を理解した後、第1部（知能分野）→第2部（知識分野）を基本の推奨順とするが、利用者が並行して進めることも妨げない。各章内はLevel 0から順に進めることを推奨するが、途中省略を禁止しない（前提知識・推奨順序を明示した上で自由度を残す。追加事項D）。第3部以降（論文・企画提案・討議・面接）は、基礎能力試験対策と並行して早期から着手することも推奨する（総合論文・企画提案は書く力の育成に時間がかかるため）。

### 5.11 問題演習の位置付け

知識定着の確認手段ではなく、**本サイトの中心教材**として位置づける（追加事項Dの趣旨）。問題を大量生産すること自体を目的とせず、各問題が「何を測るか」「章のどの到達目標に対応するか」を明示できることを条件とする。

### 5.12 学習履歴の利用方法

閲覧履歴・正誤履歴・自己評価・復習登録を記録し、次に何を復習すべきかを利用者に提示する（10番設計書）。正解率のみで機械的に難易度を上げる設計にはしない（偶然正解・条件変化への対応力等を考慮、追加事項C）。

### 5.13 運用・更新方針

年度依存情報の隔離（§4.11）、新年度の過去問追加時の既存データ非破壊（FXアプリの運用哲学を踏襲、00_調査結果.md §3.4④）、問題IDの衝突防止を運用の基本方針とする（詳細は16番設計書）。

### 5.14 品質基準

- 内容面：公式情報との整合性、事実と推測の区別、解答の一意性、誤答理由の説明の有無
- 技術面：スマートフォン表示・キーボード操作・学習履歴の永続性・データ破損耐性
- 運用面：教材追加の容易さ、既存データの非破壊、変更履歴の追跡可能性
（詳細は15_テスト品質保証設計.md）

### 5.15 完成条件

25節「最終確認」の全項目を満たし、かつ本文書§4.13の判定基準を満たすこと。

### 5.16 優先順位

1. 第0章（制度理解の入口。これがなければ全体が成立しない）
2. 基礎能力試験対策（出題数・配点が大きく、対策期間も要するため最優先）
3. 総合論文・企画提案（記述力の育成に時間がかかるため早期着手が望ましい）
4. 政策課題討議・人物試験対策（第2次試験直前期でも一定の対応が可能なため優先度はやや低い）
5. 予想問題（過去問・練習問題の整備が先行することが前提のため最後）

### 5.17 段階的な制作計画

19節のPhase 0〜4に従う（詳細は17_制作ロードマップ.md）。本文書では概略のみ示す：Phase 0（調査・設計＝本設計書一式）→ Phase 1（最小実用版）→ Phase 2（教材拡充）→ Phase 3（復習機能強化）→ Phase 4（実戦対応）。

## 6. 他の設計書との関係

本文書は全設計書の上位文書である。02〜18の各設計書は本文書の該当節を具体化するものであり、矛盾する内容を含んではならない。矛盾が発見された場合は18_未決事項と意思決定記録.mdに記録した上で本文書を改訂する。

## 7. 採用しなかった案

- **既存3サイトのような「全N部M章」を初期段階で確定的に打ち出す案**：教養区分は2026年度に年2回実施化されたばかりで一次資料の確認が完了していない論点が残るため（00_調査結果.md §4.3）、章構成は「暫定」として05番設計書で管理し、確定は見送った。
- **総合論文・企画提案等の記述式試験に「模範解答」を用意する案**：公式に模範解答が存在しないと判断されるため（00_調査結果.md §4.1）、絶対解の提示ではなく思考手順・自己採点観点の提供に方針転換した。
- **正答率のみによる自動レベルアップ案**：追加事項Cの趣旨（偶然正解等の考慮）に反するため採用しなかった。
