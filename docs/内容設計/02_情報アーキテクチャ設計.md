# 02_情報アーキテクチャ設計

## 1. この文書の目的

サイト全体のページ構造・ナビゲーション・コンテンツ種別間の関係を定める。個々のページ内部の詳細な節構成は各章詳細設計書（chapters/）に委ねる。

## 2. 対象範囲

サイトトップレベルのナビゲーション構造、章ページと問題データ（過去問・練習問題・予想問題）の関係、検索・絞り込みの情報設計、用語集・学習履歴ダッシュボードの位置付け。

## 3. 前提

`01_全体基本設計.md` §5.7の情報アーキテクチャ大枠、および既存3サイトの「部ごとサブフォルダ＋共有アセットルート直下」というフォルダ構成の思想（00_調査結果.md §3.2②・§3.3②）を前提とする。

## 4. 設計方針

- **「読む」導線と「解く」導線を分離しつつ双方向にリンクする**。章本文は説明→例題→問題という線形の学習導線を提供する一方、過去問・練習問題・予想問題は分野・Level・年度などで横断的に検索・絞り込みできる独立したライブラリとしても機能させる。
- 章の3層構造（L1メイン／L2深掘り／L3特講）は既存3サイトから思想として引き継ぐが、**問題演習中心のサイトであるため「乱造しない」を強く適用**し、深掘りが必要な章（数的推理の公式導出、時事の背景解説等）にのみ設ける。
- 全ページから「今どこにいるか」（部・章・Level）が常に分かるようにする（パンくず・サイドバー）。

## 5. 詳細仕様

### 5.1 トップレベルナビゲーション

```
ホーム
├─ 第0部　教養区分とは何か
├─ 第1部　基礎能力試験対策・知能分野
├─ 第2部　基礎能力試験対策・知識分野
├─ 第3部　総合論文試験対策
├─ 第4部　企画提案試験対策
├─ 第5部　政策課題討議試験対策
├─ 第6部　人物試験対策
├─ 第7部　学習計画・過去問活用・総仕上げ
├─ 過去問ライブラリ（年度・試験段階・分野・Levelで横断検索）
├─ 練習問題バンク（分野・Levelで横断検索）
├─ 予想問題バンク（分野・出題可能性で横断検索）
├─ 学習履歴・復習ダッシュボード
├─ 用語集
└─ 検索
```

既存3サイトの `NAV_PARTS` 配列によるnav自動生成の思想（金融ノート `fin.js`）を踏襲し、部を追加してもJSの1行追加で反映できる構成とする（12_技術基本設計.mdで規定）。

### 5.2 章ページの構造（L1メイン）

各章ページは追加事項Bの段階構造に従い、次の順で構成する：

```
章導入（具体的場面・逸話） → 用語 → 最も単純な具体例 → 基本的な考え方
  → 解説付き例題（一手ずつ） → Level0確認問題（埋め込み） → Level1確認問題（埋め込み）
  → まとめ → 章末問題演習への導線（Level2以降・過去問はページ末または別ページへ）
```

Level 0〜1程度の軽い確認問題は章本文に埋め込み表示し、Level 2以降のまとまった演習・過去問は章末リンクから「章別問題演習ページ」または「過去問ライブラリ／練習問題バンクの絞り込み結果」へ遷移する（1章に大量の問題を詰め込みページを肥大化させない）。

### 5.3 L2深掘り・L3特講の扱い

既存3サイトの命名規則（`chN-dM.html`／`chN-dM-a.html`）を踏襲するが、設置は「必要な章のみ」とし、乱造しない（株式ノートの方針を踏襲）。本サイトでのL2深掘り候補の例：数的推理の公式の完全導出、時事分野の制度的背景の詳細解説、面接でよく聞かれる質問の分類詳細。各章詳細設計書（chapters/）でL2の要否を個別に判断する。

### 5.4 問題データとページの関係

過去問・練習問題・予想問題は、章ページに埋め込み表示される問題（Level 0〜1中心）と、独立したライブラリページから絞り込んで表示される問題（Level 2以降・過去問全般）の両方から参照される、単一のデータソースを持つ（13_データ設計.mdで規定するJSON/JSスキーマに準拠）。同じ問題が「章ページ内」と「ライブラリの絞り込み結果」の両方に表示されうるが、データの実体は1つであり、表示先の重複によるデータ重複は発生させない。

### 5.5 検索・絞り込み

- **章本文検索**：既存3サイトの`build-search-index.py`方式（h1/h2/h3単位の抽出）を踏襲し、章本文・用語集を対象にする。
- **問題絞り込み**：過去問・練習問題・予想問題バンクでは、分野・Level・年度・試験段階・正誤状況（未着手／正解／不正解／要復習）による絞り込みUIを設ける。本文検索とは別の仕組み（構造化データに対するフィルタ）として設計する（04_検索絞り込み設計は本文書と09・10番の内容を踏まえて別途詳細化。詳細設計書一覧では11_UI_UX設計.mdおよび13_データ設計.mdに统合する）。

### 5.6 用語集

初出時に定義した専門用語を集約し、章から用語集への相互リンク、用語集から初出章へのリンクを張る（追加事項Bの「未説明の用語を前提としない」の補助装置）。

### 5.7 学習履歴・復習ダッシュボード

章別・Level別の進捗状況、要復習問題一覧、直近の学習履歴を1ページに集約する（詳細は10_学習履歴進捗設計.md）。

### 5.8 フォルダ構成の大枠（技術詳細は12_技術基本設計.md）

既存3サイトを踏襲し、部ごとにサブフォルダを設ける案を基本方針とする。問題データは章ページとは独立したデータディレクトリに置く（例：`data/questions/` 相当。命名は13_データ設計.mdで確定）。

## 6. 他の設計書との関係

`01_全体基本設計.md` §5.7を具体化する。`05_章構成一覧.md`で章数・部数が確定した場合、本文書§5.1のナビゲーション構造もそれに合わせて更新する。`06`〜`10`番（過去問・練習問題・予想問題・解答解説・学習履歴）、`11`（UI・UX）、`13`（データ設計）と密接に関連する。

## 7. 採用しなかった案

- **単一ページ（SPA的な1ページ完結構成）**：問題数が多くなることが見込まれ、章の読了・戻りやすさを重視するため、既存3サイトと同様の複数ページ構成を採用した（比較表は12_技術基本設計.mdに記載）。
- **章ページ内に全Levelの問題を埋め込む案**：ページの肥大化・読み込み速度低下を避けるため、Level 2以降は別ページ／絞り込み結果への導線に変更した。

## 8. リスクと注意点

- 過去問ライブラリと章ページの双方に同じ問題が現れることで、利用者が「同じ問題を重複してカウントされているのでは」と混乱する可能性がある。学習履歴は問題IDベースで一意に管理し、表示箇所が増えても履歴が二重にカウントされないことをUIで明示する必要がある（10番・13番で対応）。

## 9. 未決事項

- 検索と絞り込みを完全に統合したUIにするか、別コンポーネントとして分離するかは11_UI_UX設計.mdでの検討課題とする。
- L2深掘りを設ける章の最終リストは各章詳細設計書の作成時に確定する。

## 10. 完成条件
