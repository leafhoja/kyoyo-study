# 03_学習体験設計

## 1. この文書の目的

利用者が初めてサイトを訪れてから、日々の学習を通じて合格水準に到達するまでの体験全体を設計する。「学習計画をどう立てるか」「わからない問題にどう対処するか」「章の完了をどう判定するか」「初学者が陥りやすい誤解にどう対処するか」を扱う（第2層の分類でいう「学習計画設計」「復習設計の一部」をここに統合する。§6参照）。

## 2. 対象範囲

初回オンボーディングフロー、章の完了条件、わからない問題への対処導線、学習計画の立て方、モチベーション設計、初学者が陥りやすい誤解への対処方針。

## 3. 前提

追加事項Bの「完全な初学者を前提とした教材設計」、`01_全体基本設計.md` §4.5（インプット・演習・復習の循環）・§4.7（「読んだ」と「習得した」の区別）を前提とする。

## 4. 設計方針

- 利用者は試験制度・学習法について何も知らない状態で最初にサイトを訪れる、という前提を貫く（追加事項B）。
- 「わからない」ことを失敗として扱わず、次に何をすべきかを必ず提示する（追加事項Cの「前提問題との接続」）。
- 過剰な演出・ゲーミフィケーション（ポイント制・バッジ・ランキング等）は追加事項の「設計上の過剰機能を避ける」原則（01番§18.4相当）に従い採用しない。進捗の可視化は素朴な数値・グラフにとどめる。

## 5. 詳細仕様

### 5.1 初回訪問時のオンボーディングフロー

```
ホーム到達
→「はじめての方へ」導線（目立つ場所に常設）
→ 第0章（教養区分とは何か）への誘導
→ 第0章内「サイト内の推奨学習順序」「各章の完了条件」の説明
→ 第1部・第1章へ
```

2回目以降の訪問では、学習履歴（10番設計書）に基づき「前回の続き」「復習対象」への導線をホームまたはダッシュボードに表示する。ただし初回訪問者への配慮を損なわないよう、初回訪問時にはこれらの導線を表示しない（学習履歴が空の状態でも破綻しない設計。10_学習履歴進捗設計.mdと連携）。

### 5.2 章の完了条件の設計原則

「閲覧完了」と「Level到達」を分けて管理する（01番§4.7）。

- **閲覧完了**：章本文の主要セクションを一度最後まで表示したこと。最低限の完了条件であり、能力習得を意味しない。
- **Level到達**：そのLevelの問題群について、一定の基準（自力正解率・自己評価の質等）を満たしたこと。具体的な閾値（例：「Level2は自力正解率7割以上」等）は10_学習履歴進捗設計.mdで検討し、確定値は18番未決事項に暫定表示する。

各章詳細設計書（chapters/）は、この2種類の完了条件を明示する。

### 5.3 わからない問題に出会った場合の対処設計

利用者が問題を解けなかった場合、単に「不正解」と表示するだけで終わらせない。次の段階的対処を設計する（追加事項Cの「前提問題との接続」に対応）：

1. まずヒントを段階的に表示できる（09_解答解説設計.mdで定義するヒント段階）
2. それでも分からない場合、解答・解説を見る（見た場合は学習履歴に「解答閲覧のみ」として記録し、正解として扱わない）
3. 解説内で、前提となる章・前提となる用語・前提となる問題への導線を明示する
4. 一段階易しい類題、同難易度の類題への導線を提示する
5. 復習対象として登録できる

この一連の流れは、章本文中の確認問題・独立ライブラリの練習問題のいずれでも同じ体験になるよう統一する。

### 5.4 学習計画設計

- サイトは固定的な「試験まで残り◯日」の表示を行わない（プロジェクト目的§1、01番§5.2）。
- 第0章・第7部で「サイト内の推奨学習順序」（01番§5.10）を明示し、利用者が自分のペースで参照できるようにする。
- 任意の試験日を入力し、残り期間に応じて推奨ペースを調整する機能は、**将来的な検討課題**として設計上排除しない（プロジェクト目的§1で明示的に許容）。実装するかどうかは18番未決事項とし、Phase 3以降（復習機能強化・実戦対応）での検討候補とする（17_制作ロードマップ.md）。
- 学習計画は「絶対的なスケジュール表」ではなく、「今何を優先すべきか」を学習履歴から示すダッシュボード（10番）と一体で機能させる。

### 5.5 モチベーション設計

- 進捗の可視化は、章別・Level別の素朴な達成状況（例：「Level2 12/20問正解」）にとどめ、他者との比較・ランキング・過度な演出は行わない（想定利用者が1名のみであるため、比較機能自体が不要）。
- 既存3サイトの「コラム」（歴史の一コマ）の手法を、本サイトでは「学習の合間の息抜き」として抑制的に使う（00_調査結果.md §3.3⑤）。試験対策の緊張感を保ちつつ、燃え尽きを防ぐ位置付け。

### 5.6 初学者が陥りやすい誤解への対処方針

第0章（chapters/00_試験概要_詳細設計.md）で、少なくとも次の誤解を明示的に取り上げ、正しい理解を示す：

1. 「教養区分は専門試験がないから簡単」という誤解（総合論文・企画提案・討議・面接という別の負荷が高い試験があることを説明）
2. 「総合論文試験は学校の小論文と同じ」という誤解（教養・哲学的な考え方を問う特有の出題であることを説明、00_調査結果.md §4.1）
3. 「基礎能力試験さえ突破すればよい」という誤解（第1次合格判定は基礎能力試験のみだが、総合論文は最終合格判定に合算されること、00_調査結果.md §4.1）
4. 「過去問を早く大量に解けば合格できる」という誤解（追加事項Bの段階構造に反する学習法であることを説明し、正しい順序を提示）
5. 「一度解けた問題はもう見なくてよい」という誤解（復習の重要性、10番設計書の趣旨を第0章で予告）

## 6. 他の設計書との関係

第2層の分類でいう「学習計画設計」は本文書§5.4に、「復習設計」の一部（わからない問題への対処導線）は本文書§5.3と10_学習履歴進捗設計.mdに分担して格納する。chapters/00_試験概要_詳細設計.mdは本文書§5.1・§5.6を具体化する。09_解答解説設計.mdは§5.3のヒント段階を詳細化する。

## 7. 採用しなかった案

- ポイント・バッジ・連続ログイン記録等のゲーミフィケーション要素：想定利用者が1名であり、過剰機能を避ける原則（01番§18.4）に反するため採用しなかった。
- 固定的な「試験まで残り◯日」カウントダウン表示：プロジェクト目的で明示的に禁止されているため採用しなかった。

## 8. リスクと注意点

- 学習計画に「任意の試験日設定」を将来追加する場合、学習履歴データとの整合（進捗集計の基準日をどこに置くか）を事前に想定しておく必要がある（13_データ設計.mdで拡張余地を残す）。

## 9. 未決事項

- Level到達の具体的な閾値（自力正解率の基準値等）
- 任意の試験日設定機能を実装するか、するとすればどのPhaseで行うか

## 10. 完成条件

初回オンボーディング、章完了条件の原則、わからない問題への対処導線、学習計画の基本方針、モチベーション設計、初学者が陥りやすい誤解のリストが揃っていること。
