# 04_コンテンツ全体設計

## 1. この文書の目的

サイト全体で使うコンテンツ種別・文体・表示コンポーネント・用語集の管理方針・事実と推測の区別ルールを横断的に定める。個々の章の内容そのものはchapters/、問題データの形式は06〜08番・13番に委ねる。

## 2. 対象範囲

コンテンツ種別一覧、語り口・文体方針、box系コンポーネント、難易度表示、用語集設計、モデル使い分け方針、事実と推測の区別表示ルール。

## 3. 前提

`00_調査結果.md` §3.2〜3.3（既存3サイトからの踏襲・修正事項）、追加事項B・Cを前提とする。

## 4. 設計方針

- 既存3サイトのbox系コンポーネントの思想を継承しつつ、問題演習中心のサイトに合わせて拡張する。
- 難易度表示は追加事項Cの6段階（Level 0〜5）で統一し、既存3サイトの3段階（★基礎/★★標準/★★★発展）の用途（章本文の解説難易度）とは役割を分離する。
- 断定表現と推測表現を語彙レベルで統一し、事実／年度依存／設計上の仮定／予想を混同しない（00_調査結果.md §4.3・01番§4.10）。

## 5. 詳細仕様

### 5.1 コンテンツ種別一覧

`01_全体基本設計.md` §5.9のコンテンツ種別を再掲し、各種別の主な置き場所を示す：

| 種別 | 置き場所 | 主要設計書 |
|---|---|---|
| 章本文 | 各部フォルダの章ページ | chapters/、02番 |
| 例題 | 章本文内 | chapters/、09番 |
| 練習問題 | 章内埋め込み（Level0-1）＋練習問題バンク（Level2-5） | 07番 |
| 過去問 | 過去問ライブラリ | 06番 |
| 予想問題 | 予想問題バンク | 08番 |
| 解答・解説 | 各問題に付随 | 09番 |
| 学習計画・過去問活用ガイド | 第7部 | 03番 |
| 用語集 | 独立ページ＋章内リンク | 本文書§5.5 |
| 学習履歴・復習ダッシュボード | 独立ページ | 10番 |

### 5.2 語り口・文体方針

- 各分野の導入は具体的な場面・逸話・逆説から入り、いきなり定義や過去問から入らない（追加事項B「説明の段階構造」）。
- 専門用語は初出時に「定義・具体例・試験での意味」を必ず説明し、まだ説明していない別の専門用語を当然のように使わない（追加事項B）。
- 既存3サイトの「あなたが〜したとする」という語りかけ、比喩を積極的に使う語り口を踏襲するが、本サイトは試験対策が主目的のため、コラム的な逸話は抑制的に配置する（03番§5.5）。
- 総合論文・企画提案対策（第3部・第4部）は「教養・哲学的な考え方」（00_調査結果.md §4.1）を扱うため、単なる文章作法ではなく思考プロセスの解説に重心を置く。

### 5.3 box系コンポーネント（既存3サイトからの拡張）

| クラス | 用途 | 備考 |
|---|---|---|
| `box-def` | 定義（専門用語・制度用語） | 既存踏襲 |
| `box-thm` | 法則・公式（数的推理・資料解釈等） | 既存踏襲 |
| `box-ex` | 例・具体計算・具体例 | 既存踏襲 |
| `box-note` | 注意・よくある誤解 | 既存踏襲。03番§5.6の誤解リストと連動 |
| `box-imp` | 重要ポイント・まとめ | 既存踏襲 |
| `box-prf` | 導出・完全な計算過程（折り畳み） | 既存踏襲 |
| `box-now` | 年度依存の制度情報（配点・日程・倍率等） | 既存の「現在の視点」思想を継承し、必ず確認日・出典を明記（00_調査結果.md §4.2） |
| `box-q`（新設） | 章内埋め込みの確認問題（Level0-1） | 解答は`details`/`summary`相当で開閉（11番） |
| `box-wrong`（新設） | 誤答分析・よくある誤答パターン | 09_解答解説設計.mdの「誤答選択肢の分析」と対応 |
| `box-forecast`（新設） | 予想問題の「予想根拠」表示 | 08番設計書の必須項目と対応。断定表現を含めない |

### 5.4 難易度表示（追加事項C準拠）

| Level | 名称 | 用途 |
|---|---|---|
| 0 | はじめの一歩 | 問題形式・操作確認 |
| 1 | 基礎確認 | 単一知識の確認 |
| 2 | 基本 | 基本問題 |
| 3 | 標準 | 標準問題 |
| 4 | 実戦 | 応用・実戦問題 |
| 5 | 高難度 | 高難度・予想問題 |

章本文の解説自体の難易度表示（既存3サイトの★基礎/★★標準/★★★発展）は残してよいが、「問題」の難易度は必ずLevel 0〜5で表示し、両者を混同する表記をしない（00_調査結果.md §3.3①）。名称は正式設計時（実装フェーズ）に全体の文体と再度整合させてよい（追加事項C原則、暫定扱い）。

### 5.5 用語集設計

- 初出時に`box-def`で定義した用語は、原則すべて用語集に集約する。
- 用語集の1エントリは「用語（読み方・英語併記があれば）」「定義」「初出章へのリンク」「関連用語」を持つ。
- 追加事項Bの「未説明の専門用語を前提としない」を用語集自体でも徹底し、用語集内の説明文でも未定義の用語を使わない。

### 5.6 モデルの使い分け方針

既存3サイトの「Fable＝語り口の魅力、Sonnet＝構造・正確性」という役割分担（00_調査結果.md §3.2⑥）を踏襲する。

| 部・章 | 推奨モデル | 理由 |
|---|---|---|
| 第0部（制度理解） | Sonnet | 制度の正確性が最優先 |
| 第1部（知能分野） | Sonnet | 解法の正確性・論理構造が最優先 |
| 第2部（知識分野） | Sonnet（一部Fableで導入部の逸話を補強可） | 知識の正確性が最優先だが、歴史・時事の逸話部分は語り口を活かせる |
| 第3部（総合論文） | Sonnet | 思考の構造化が最優先 |
| 第4部（企画提案） | Sonnet | 資料分析・構成の正確性が最優先 |
| 第5部（政策課題討議） | Sonnet | 進行・評価観点の正確性が最優先 |
| 第6部（人物試験） | Fable寄りで検討可 | 対人的な内容で語り口の親しみやすさが活きる |
| 第7部（総仕上げ） | Fable | 学習の全体像を語る卒業制作的な位置付け（既存3サイトの卒業制作章の扱いを踏襲） |

両モデルとも部内で並走させず、部の性質に応じて使い分ける（既存運用ルールを踏襲、00_調査結果.md §3.2⑥）。

### 5.7 事実と推測の区別表示ルール

01番§4.10・18.3相当の原則を、具体的な表現レベルで統一する：

| 区分 | 使用表現の例 | 適用対象 |
|---|---|---|
| 公式に確認された事実 | 「〜である」「人事院によれば〜」 | 00_調査結果.md §4.1相当の内容、過去問の出題実績 |
| 過去問から観察される傾向 | 「過去の出題では〜が多い」 | 06番の出題傾向分析 |
| 制作者による分析 | 「〜と考えられる」「〜という見方ができる」 | 解説文中の解釈 |
| 予想 | 「〜が出題される可能性がある」（断定しない） | 08番の予想問題 |
| 暫定的な仮説・未確認事項 | 「〜は未確認」「〜と見られるが要確認」 | 00_調査結果.md §4.3相当の内容 |

「必ず出る」「絶対に落とせない」等の断定的な煽り表現は予想問題・出題予想解説では使用しない（プロジェクト目的§8）。

## 6. 他の設計書との関係

06〜09番（過去問・練習問題・予想問題・解答解説）はすべて本文書のbox定義・難易度表示・事実区別ルールに従う。11_UI_UX設計.mdは`box-q`の開閉挙動を技術的に規定する。16_運用更新設計.mdは`box-now`の更新運用を規定する。

## 7. 採用しなかった案

- 問題の難易度も既存3サイトと同じ3段階（★）で表示する案：追加事項Cが求める段階的難易度上昇（6段階）を表現できないため採用しなかった。
- 断定的な出題予想の見出し表現（「頻出」「必出」等の強い言い切り）：予想と事実の混同を招くため採用しなかった。

## 8. リスクと注意点

- box系コンポーネントを新設しすぎると実装コストが増大するため、`box-q`・`box-wrong`・`box-forecast`の3種にとどめ、必要以上に細分化しない。

## 9. 未決事項

- Level名称（はじめの一歩／基礎確認等）は実装フェーズでサイト全体の文体と最終調整する（追加事項C原則により暫定扱い）。
- 第6部のモデル選択（Fable寄り）は試験的判断であり、実装時の文章サンプルを見て再検討してもよい。

## 10. 完成条件

コンテンツ種別一覧、box系コンポーネント一覧、難易度表示、用語集設計、モデル使い分け方針、事実と推測の区別ルールがすべて記述され、既存3サイトからの継承・変更点が明示されていること。
