# 07_練習問題設計

## 1. この文書の目的

追加事項Dにより差し替えられた「練習問題の設計」方針を、国家総合職〈教養区分〉サイトに具体化する。練習問題は知識確認の手段ではなく、**完全な初学者が本番水準へ段階的に到達するための中心的な教材**として設計する。

## 2. 対象範囲

練習問題の種類、Level 0〜5の難易度体系の各分野への適用、問題ごとのメタデータ、問題群の構造、前提問題との接続、記述式・面接系科目における代替設計。

## 3. 前提

追加事項B（完全な初学者前提）・C（難易度の段階的上昇）・D（練習問題設計の差し替え）を前提とする。`04_コンテンツ全体設計.md` §5.4の難易度表示、`05_章構成一覧.md`の全17章を対象とする。

## 4. 設計方針

- 利用者が既に基礎知識を持っていることを前提としない（追加事項D）。
- 各分野で、最も簡単な例題と操作確認問題から始め、少しずつ難易度を上げる（追加事項D）。
- 問題を大量に作ること自体を目的とせず、各問題が「何を測るか」「章のどの到達目標に対応するか」を明示できることを条件とする（追加事項D）。

## 5. 詳細仕様

### 5.1 練習問題の種類（追加事項Dの一覧を教養区分向けに具体化）

| 種類 | 教養区分での具体例 |
|---|---|
| 問題形式を理解するための導入問題 | 「この判断推理の問題では、選択肢の中から正しい記述を1つ選ぶ」という形式そのものを確認する問題（Level0） |
| 用語を確認する問題 | 「命題」「対偶」等の用語の意味を選ぶだけの問題（Level0〜1） |
| 解説を見ながら解く例題 | 章本文中の「解法を一手ずつ示した例題」と一体化 |
| 単一知識の基礎確認問題 | 1つの公式・1つの法則のみを使う問題（Level1） |
| 直前の例題と同じ型の問題 | 例題と数値・題材だけを変えた問題（Level1〜2） |
| 条件を1つだけ変えた問題 | 例題に1条件加えた問題（Level2〜3） |
| 典型問題 | 基礎能力試験で頻出の型（Level2〜3） |
| 解法手順確認問題 | 手順を穴埋め式で確認する問題（Level1〜2、数的推理・資料解釈向け） |
| 弱点補強問題 | 学習履歴（10番）で誤答が多い論点を狙い撃ちする問題（Level2〜3、復習対象専用） |
| 複数知識を組み合わせる問題 | 判断推理＋数的推理の複合、資料解釈＋時事の複合等（Level3〜4） |
| 時間制限付き問題 | 本番の目標時間を意識した演習（Level3〜5） |
| 複数分野を横断する問題 | 知識分野を横断する時事関連問題等（Level3〜4） |
| 記述練習 | 総合論文・企画提案向けの構成メモ作成等（§5.6） |
| 判断・推論練習 | 政策課題討議の論点整理練習（§5.6） |
| 本番形式のセット問題 | 基礎能力試験Ⅰ部30題・Ⅱ部20題を模したセット（Level5） |
| 復習専用問題 | 過去に誤答した問題の再出題（10番の復習対象と連動） |
| 高難度問題 | 予想問題（08番）・過去問（06番）の高難度帯と接続 |

すべての種類を機械的にすべての章へ適用するのではなく、各章詳細設計書（chapters/）で、その章の性質に合った種類を選択する。

### 5.2 難易度体系（Level 0〜5）の分野別適用

追加事項Cの6段階を、基礎能力試験系科目（ch1〜ch8）に適用する。

| Level | 名称 | 判断推理・数的推理・資料解釈での例 | 知識分野（自然・人文・社会科学・時事）での例 |
|---|---|---|---|
| 0 | はじめの一歩 | 問題文の読み方、選択肢の選び方の確認。正誤よりも形式理解を重視、ヒント常時表示 | 用語の意味を選ぶだけの一問一答 |
| 1 | 基礎確認 | 1つの公式・法則のみを使う、手数の少ない問題 | 1つの事実・年号・定義のみを問う問題 |
| 2 | 基本 | 典型的な出題形式、ヒントなしで解けることが目標 | 典型的な一問一答・正誤判定 |
| 3 | 標準 | 複数の手順を組み合わせる、時間を意識した演習 | 複数の知識を関連づける問題（例：年代整序、比較） |
| 4 | 実戦 | 見慣れない設定、不要な情報や紛らわしい選択肢を含む | 分野横断の知識問題、資料と組み合わせた問題 |
| 5 | 高難度 | 本番相当の複雑な条件整理、複数分野の統合 | 時事と絡めた発展的な問題、予想問題との接続 |

すべての章がLevel5まで持つ必要はない（追加事項C）。試験上の重要性・出題頻度が低い論点に過剰な高難度問題を設けない。

### 5.3 問題ごとのメタデータ

各問題は、少なくとも次を明示できる設計にする（追加事項D）。これは仕様説明用の項目一覧であり、実装は行わない：

- 何を測る問題なのか
- どの章のどの到達目標に対応するか
- 難易度（Level 0〜5）
- 推奨学習順序（`sequenceOrder`相当）
- 必要な前提知識
- 前提問題（`prerequisiteQuestionIds`相当）
- 解けなかった場合に戻る教材
- 次に進む問題
- 想定解答時間
- ヒントの段階（09番で規定する段階数と対応）
- 典型的な誤答
- 誤答の原因
- 自力で解くべき範囲（ヒントに頼ってよい範囲との境界）

技術設計としてのデータ構造は`13_データ設計.md`に委ねる（プロジェクト仕様書7節の趣旨どおり、ここではJSON例は仕様説明用にとどめる）。

### 5.4 問題群の構造

各章の問題群は、原則として次の構造を持つ（追加事項D）：

```
考え方の説明
→ 解説付き例題
→ 極めて簡単な確認問題（Level0）
→ 基礎問題（Level1）
→ 基本問題（Level2）
→ 標準問題（Level3）
→ 応用問題（Level4）
→ 本番形式問題（Level5、過去問への導線を含む）
```

利用者が途中の段階を飛ばして高難度問題へ進むこと自体は禁止しないが、推奨学習順序と必要な前提知識を明示する（追加事項D）。

### 5.5 前提問題との接続・戻り先の設計

各問題について、必要に応じて次を記録できる設計にする（追加事項C）：前提となる章・前提となる用語・前提となる問題・推奨される直前問題・解けなかった場合に戻る教材・次に進むべき問題・同難易度の類題・一段階易しい問題・一段階難しい問題。解けなかった場合に「基礎から復習」という曖昧な案内で終わらせず、具体的な章・項目・問題を提示する（追加事項D）。

### 5.6 記述式・面接系科目における代替設計（ch9〜ch14）

総合論文（ch9・ch10）・企画提案（ch11・ch12）・政策課題討議（ch13）・人物試験（ch14）は、正誤が一意に決まらない。これらの科目では「問題」を次のように読み替える：

- Level0〜1相当：構成要素（総合論文の「問い」の分解、企画提案の「現状分析・課題・提案」の型など）を穴埋め・選択形式で確認する問題
- Level2〜3相当：短いお題に対する構成メモ作成（本文執筆までは求めない）
- Level4相当：時間を区切った構成メモ〜要点作成の演習
- Level5相当：本番相当の時間制約での模擬演習（本文執筆、プレゼン原稿作成、討議の論点整理など）

正誤の代わりに、09_解答解説設計.mdで定める「評価観点チェックリスト」による自己採点と、振り返りメモの記録を用いる。

### 5.7 問題を大量生産しないための歯止め

各問題は§5.3のメタデータ（特に「何を測るか」「どの到達目標に対応するか」）を明示できない場合は作成しない（追加事項D）。章ごとの問題数は、到達目標の数・分野の重要度に応じて章詳細設計書で個別に定め、全章一律の問題数を機械的に割り当てない。

## 6. 他の設計書との関係

`05_章構成一覧.md`の全17章を対象とする。`09_解答解説設計.md`はヒント段階・評価観点チェックリストを詳細化する。`10_学習履歴進捗設計.md`は本文書のLevel別進捗を集計する。`13_データ設計.md`は本文書§5.3のメタデータを技術的なスキーマへ落とし込む。

## 7. 採用しなかった案

- 全章に一律の問題数（例：各章100問）を割り当てる案：問題を大量に作ること自体が目的化するため採用しなかった（追加事項D）。
- 記述式・面接系科目にも多肢選択式の疑似問題だけを用意する案：測定したい能力（構成力・対人力）と乖離するため、§5.6の代替設計を採用した。

## 8. リスクと注意点

- Level0〜1の問題を作りすぎると、利用者の学習時間の多くが「操作確認」に割かれてしまうリスクがある。各章の到達目標に照らして最小限にとどめる。

## 9. 未決事項

- ch13・ch14（討議・面接）を「練習問題バンク」の絞り込み対象に含めるか、章内専用の演習として閉じるか（05番の未決事項と同一、18番へ集約）
- 各章のLevel別問題数の目安（章詳細設計書作成時に個別決定）

## 10. 完成条件

練習問題の種類・Level別適用例・メタデータ・問題群の構造・前提問題接続・記述式代替設計が、全17章に適用可能な形で記述されていること。
