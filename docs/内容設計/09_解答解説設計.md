# 09_解答解説設計

## 1. この文書の目的

過去問・練習問題・予想問題に共通する「解答・解説」の内容設計を定める。ヒントの段階、詳細解説の構成、誤答分析、記述式・面接系科目における評価観点チェックリストを扱う。画面上の開閉動作そのもの（アコーディオンの実装方式）は`11_UI_UX設計.md`に委ねる。

## 2. 対象範囲

ヒント段階、解答・解説の構成要素、誤答分析、別解、記述式・面接系科目の代替評価設計、正誤記録前後の利用者操作。

## 3. 前提

プロジェクト仕様書9節（問題画面の基本挙動）・10節（学習記録）、`07_練習問題設計.md`§5.3（ヒントの段階というメタデータ項目）を前提とする。

## 4. 設計方針

- 「解答を見る前に自分の回答を記録できる」ことを基本挙動とし、解答を見てから正誤を判断する（当てずっぽうの正解を自覚できるようにする）流れを軸にする。
- ヒント・解説・誤答分析は一度にすべて開示せず、段階的に開示できるようにする（追加事項Cの「ヒント使用後の正解率」等の分析にも対応）。
- 記述式・面接系科目は、正誤に代わる「評価観点チェックリスト」による自己採点を用いる。

## 5. 詳細仕様

### 5.1 多肢選択式問題（過去問・練習問題・予想問題）の基本挙動

```
1. 問題文表示（選択肢含む）
2. 利用者が自分の回答を選択・記録する（この時点では正誤を明かさない）
3. 「解答を見る」操作で正解・詳細解説を表示する
4. 利用者が正解／不正解／一部正解／要復習／判断保留のいずれかを自己記録する
5. 解答を見た後でも、正誤の自己記録を修正できる
6. 誤答選択肢の分析・別解を、詳細解説の中で段階的に開示できる
7. 関連する解説章・前提章・類題（易しい／同難易度／難しい）への導線を表示する
8. 次の問題・前の問題への導線を表示する
```

### 5.2 ヒントの段階設計

問題ごとに、次のような段階的ヒントを持てるようにする（すべての問題に全段階を用意する必要はない）：

1. **方向性のヒント**：どの知識・どの解法を使う問題かを示す（正解そのものは明かさない）
2. **手順のヒント**：解法の最初の一手を示す
3. **部分的な解答のヒント**：計算の途中経過や、選択肢の一部を絞り込む情報を示す
4. **完全な解答・解説**：正解と詳細解説

Level 0の問題は、追加事項Cの趣旨（「必要に応じてヒントを常時表示する」）に従い、初期状態からヒントを開いた状態で表示することも許容する。

### 5.3 詳細解説の構成要素

- 解法手順（一手ずつ、Level0〜1の例題と同じ粒度で示す）
- 別解（存在する場合。特に数的推理・資料解釈は複数の解法があることが多い）
- 誤答選択肢の分析（§5.4）
- 必要な前提知識・前提章への導線
- 関連する過去問・類題への導線

### 5.4 誤答分析（`box-wrong`）の内容設計

各誤答選択肢について、次を明示する：

- なぜその選択肢を選んでしまうのか（典型的な誤解・計算ミスのパターン）
- その誤りに気づくための着眼点
- 該当する誤りパターンが、学習履歴（10番）の自己評価「ケアレスミス」「理解不足で不正解」等とどう対応するか

### 5.5 記述式・面接系科目（ch9〜ch14）の解答解説設計

総合論文・企画提案・政策課題討議・人物試験には公式の模範解答・採点基準が存在しない（`00_調査結果.md` §4.1）。これらの科目では次を用いる：

- **模範解答の代わりに「解答の方向性」**：複数の妥当な構成例を示し、「これが唯一の正解」という提示はしない。
- **採点基準の代わりに「評価観点チェックリスト」**：例えば総合論文であれば「問いを正確に捉えているか」「複数の視点から論じているか」「結論が問いに対応しているか」等、公開情報や一般的な論述評価の観点から構成する（人事院非公表であることを明記した上での、学習用の自己点検ツールと位置付ける）。
- **振り返りメモ**：模擬演習後に、自分の解答の強み・弱みを自由記述で記録できるようにする（学習履歴側に保存、10番）。

これらの科目で「正解」「模範解答」という言葉を使う場合は、必ず「人事院により公式に公表されたものではない」旨を明記する（04番§5.7の事実区別ルール）。

### 5.6 正誤記録の区分（内容設計上の定義。保存自体は10番）

- 正解
- 不正解
- 一部正解
- 要復習（正解だが理解が浅いと自覚した場合等）
- 判断保留（記述式・討議・面接系で、自己採点が難しい場合）

### 5.7 解答を見た後の自己修正

解答・解説を見た後に、利用者が「実は理解して解けていた」「実は当てずっぽうだった」と気づくことは自然であるため、正誤の自己記録はいつでも修正できるようにする（プロジェクト仕様書9節）。

## 6. 他の設計書との関係

`11_UI_UX設計.md`は本文書§5.1〜5.2の挙動をアコーディオン等の技術要素として実装する方式を規定する。`10_学習履歴進捗設計.md`は§5.6の正誤区分・振り返りメモを実際に保存・集計する。`07_練習問題設計.md`のヒントメタデータ項目と§5.2は対応する。

## 7. 採用しなかった案

- 記述式・面接系科目に対して、多肢選択式と同じ「正解／不正解」の二値記録を強制する案：測定したい能力の性質と合わないため、評価観点チェックリスト＋振り返りメモの方式に変更した。

## 8. リスクと注意点

- 評価観点チェックリストが「公式の採点基準であるかのように」誤解されないよう、学習用の自己点検ツールである旨をすべての記述式科目ページで明記する必要がある。

## 9. 未決事項

- 評価観点チェックリストの具体的な項目（総合論文・企画提案・討議・面接それぞれ）は、chapters/該当章の詳細設計時に確定する。

## 10. 完成条件

多肢選択式・記述式双方の解答解説フロー、ヒント段階、誤答分析、正誤記録区分が記述され、07番・10番・11番との対応が取れていること。
